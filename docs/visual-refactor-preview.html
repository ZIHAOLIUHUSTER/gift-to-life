设计基础

先定层级与字阶，再谈页面

整个重构只有四层材质关系，和一张字阶表。下面所有页面都只使用这两样东西——不再新增卡片样式、色块和装饰。

四层材质：纸面 · 白玉 · 墨字 · 青松落款

纸面
画布：背景色，只承托，不表达信息。整屏占比最大。
白玉
内容面：白卡，只承载真正的内容与分组。数量严格控制。
墨字
文字：正文用 onSurface，元信息用 onSurfaceVariant。
青松
点睛：主色只落在一处——主按钮、选中态、光标或一根细线。
量化目标：中性骨架 ≥ 95% 感知面积，主色 ≤ 5%。主按钮之外， 普通内容屏不出现高度超过 48dp 的连续主色面。

回忆页

V2 · MemoryScreen / AppEmptyState

随机回顾去掉 460dp “大片空白”式定高和整卡主色底，改成**定高外壳 + 固定 200dp 内容区**： 跳条目时卡片尺寸不变，只有内容区在换；周志 / 月志 / 那年今日合成一个分组面，不再是一排按钮和零散卡片。

随机回顾卡：三种内容排布，外壳尺寸完全一致

三种排布共用同一个定高外壳与固定 200dp 内容区 —— 所以从“短文”跳到“带图”也不会推动下面的元信息行。

切换不抖：「再抽一条」可以真的点

下面是可交互的：连点十几次试试。卡片外壳、元信息行、按钮位置全程不动，只有内容区与元信息文字在换。

已点 0 次 · 按钮从不冷却，连点每次都生效

现在的抖是怎么来的（当前实现）

  • Crossfade 同时叠着两份完整布局：新旧模板不同（有图/无图、短/长）就是“抖”的主要来源
  • 内容框与下方 Spacer 各占一半权重 → 元信息行不锚底，长短文之间会上下移动
  • 长文超过可用高度时，把元信息与按钮一起往下推
  • 「再抽一条」点击后禁用 300ms → 连点被吞

新规则（已写进执行稿 §5.2.3）

  • 定高外壳 + 固定 200dp 内容区，卡片尺寸与内容无关
  • 只保留一份内容实例，直接换内容，不做 Crossfade
  • 图片位永远预留 140dp，不管图有没有加载完
  • 长文裁切，不推挤底部；“查看全文”只在被裁时出现
  • 按钮永不禁用；防重入只在内部丢弃并发请求
